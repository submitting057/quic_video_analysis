# 元数据文件说明

YouTube 加密视频自动化采集系统为每次采集会话生成一个 `.metadata` 文件，以 JSON 格式记录该会话的完整元数据，主要用于关联 PCAP 抓包文件与采集环境上下文。

## 文件定位

`.metadata` 文件是 PCAP 数据与采集环境之间的"索引卡"，记录了"在什么环境下、用什么参数、抓了什么流量"。它与 `operate.log`、`debug_info.txt`、`adb_log.txt` 同属一次采集会话的产出物，但侧重点不同——前者关注流量文件和环境参数，后者关注操作流程和播放器状态。

## 文件命名规则

`.metadata` 文件与同会话的其他文件共享同一前缀：

```
YouTube-EncryptedVideo-Android-{session_id}-{network_type}-{network_detail}-{timestamp}-{device}-{video_id}-{resolution_mode}-{app}-{region}.metadata
```

以本次会话为例：

```
YouTube-EncryptedVideo-Android-3a9d9d25a6424928937939c36842a1df-Wifi-Open-20260613_234015-yb01-ENt4uip1MJ8-auto-YouTube-HongKong.metadata
```

命名规则与日志文件完全一致，通过前缀即可将 `.metadata` 与 `.operate.log`、`debug_info.txt`、`adb_log.txt` 关联到同一会话。

## 内容结构

文件为单条 JSON 对象，各字段按逻辑分组如下：

### 会话标识

| 字段 | 示例值 | 说明 |
|------|--------|------|
| `capture_id` | `3a9d9d25a6424928937939c36842a1df` | 采集会话唯一标识（UUID），与文件名中的 `session_id` 一致 |
| `capture_time` | `2026-06-13T23:40:40` | 采集启动时间（ISO 8601 格式） |
| `capture_end_time` | `2026-06-13T23:46:27` | 采集结束时间（ISO 8601 格式） |

### 环境信息

| 字段 | 示例值 | 说明 |

## 与其他文件的关联关系

```
.metadata                operate.log            debug_info.txt         adb_log.txt
(PCAP 索引与环境参数)     (任务编排层)            (应用状态层)            (系统底层)
    |                       |                      |                      |
    |-- capture_id ---------|-- session_id ---------|                      |
    |   (会话唯一标识)       |  (文件名中的UUID)      |                      |
    |                       |                      |                      |
    |-- phone_to_server_time_offset                 |                      |
    |   (时间偏移，与 operate.log 中的值一致)         |                      |
    |                       |                      |                      |
    |-- file_name ──→ PCAP 文件                     |                      |
    |   (关联抓包数据)       |                      |                      |
    |                       |                      |                      |
    |-- device_mode ────────|──────────────────────|-- Device 字段         |
    |   (设备型号编码)       |                      |  (debug_info 中)      |
    |                       |                      |                      |
    +---------- 时间对齐 ---+---------- 时间对齐 ---+---------- 时间对齐 ---+
              (phone_to_server_time_offset + 本地时间戳)
```

关键关联点：

- **`capture_id` = 文件名中的 `session_id`**：通过 UUID 将 `.metadata` 与同会话的所有日志文件绑定。
- **`phone_to_server_time_offset`**：与 `operate.log` 中记录的值相同，是时间对齐的核心参数。
- **`file_name` 指向 PCAP 文件**：PCAP 文件可能存储在 `file_path` 指定的路径中，而非日志文件所在目录。
- **`device_mode` 与 `debug_info.txt` 中的 Device 字段型号一致**：可交叉验证设备信息。

## 典型用途

- **数据集构建**：`.metadata` 的分类体系（`lv1`~`lv4_category`）和采集参数为批量数据集的筛选、分组和统计提供结构化索引。
- **PCAP 定位**：通过 `file_name` 和 `file_path` 找到对应的抓包文件，将流量数据与采集上下文关联。
- **环境复现**：`network_information`、`device_mode`、`os_version` 等字段记录了完整的采集环境，支持实验复现。
- **时间对齐验证**：`phone_to_server_time_offset` 和 `capture_time`/`capture_end_time` 为跨设备时间线对齐提供参考。
