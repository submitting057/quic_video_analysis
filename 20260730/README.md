# 2026-07-30：采集日志、元数据与 PCAP 预处理

## 概述

本目录说明 YouTube 加密视频自动化采集系统生成的日志与元数据，并在这些采集条件基础上定义面向 packet-level 深度学习的 PCAP 原始数据预处理流程。

## 核心结论

- 三种日志分别对应任务编排层、应用状态层和系统底层，协作支撑从采集到分析的全流程。
- operate.log 是理解采集上下文的首选入口，记录了完整的自动化操作流程。
- debug_info.txt 是 ABR 自适应码率与缓冲行为分析的主要数据源，以约 4 秒间隔采集 YouTube "Stats for Nerds" 快照。
- adb_log.txt 体量大但提供系统级深挖能力，建议按标签或 PID 过滤使用。
- 时间对齐是三者协作的核心，operate.log 中的 `phone_to_server_time_offset` 可将设备时间与 PCAP 抓包时间关联。
- .metadata 文件是 PCAP 数据与采集环境的索引卡，记录会话元数据、设备信息、分类体系和采集参数，通过 `capture_id` 与日志文件关联，通过 `file_name` 定位 PCAP 抓包文件。
- PCAP 预处理以一个重组后的 UDP Datagram 为基本事件，先生成完整审计表，再生成不含 IP、端口、CID 和绝对时间的模型基础事件表。
- 当前阶段保留原始包长、方向、相对时间和路径关系，不提前执行归一化、固定窗口、Padding 或 Burst 聚合。
