# 2026-08-04：实测 PCAP 分析、视频段截取与预处理方案验证

## 概述

本目录基于一份真实的 YouTube QUIC 加密视频 PCAP（视频 ID: ENt4uip1MJ8, 77,212 包, 335 秒）进行全流程分析，覆盖从逐包解析、视频数据起止判断到预处理方案实测验证的完整链条。分析结果对 [20260728](../20260728/README.md) 和 [20260730](../20260730/README.md) 中的设计假设进行了实证检验，并提出了修正和优化。

## 核心结论

- 前 20 个包仅包含 DNS 解析和 QUIC Initial 握手，无视频数据传输；视频数据从约 5.5 秒后开始到达。
- 视频数据的起止可通过 DNS 域名映射（`*.googlevideo.com`）+ 吞吐量突发检测可靠判定，无需解密。
- **DCID 在服务器→客户端 1-RTT 包中 0% 可见**，连接追踪必须依赖五元组并在握手阶段建立映射。
- 8192 事件上限不足以覆盖高吞吐 30 秒窗口（实测可达 10,066），建议提升至 16384。
- 包大小三档中 medium 档几乎为空，建议将上界从 1000B 调整为 800B。
- 新增"视频段自动定位"步骤，填补文档在 PCAP 级自动检测方面的空白。
- 文档的核心设计（事件定义、归一化策略、数据划分规则、反 shortcut 实验框架）经验证合理，无需修改。
