# 2026-11-18：QUIC 多流复用下目标视频与预取视频分离方案

## 本次内容

Snapchat 等短视频应用会把目标视频（当前播放）与预取推荐视频混合在同一个
QUIC 连接中传输。由于 1-RTT 包中 stream ID 与 HTTP/3 头部均被加密，被动观察者
无法直接按 stream 拆分。本次讨论给出一个"事务重建 + 事务归属"的分离（初筛）
方案，并配套 ground truth 采集、受控实验与评估设计。

## 核心结论

1. **问题转化**：无法按 stream 拆分时，转为两步——从加密包序列重建
   "请求 → 响应"事务，再判断每个事务属于目标视频还是预取；
2. **ground truth 闭环**：先用可解密数据回答四个关键问题（是否同连接、预取是否为
   前缀、并发与服务器调度方式、预取提升后是否命中缓存），再据此校准阈值与训练分类器；
3. **事务切分**：基于上行请求包长度检测请求，结合 RTT、尾包与空闲间隔、服务器
   调度模型（顺序 / 交错）分配下行字节；
4. **目标/预取分类**：利用触发时机（跨连接滑动标记）、批量并发形态、对象大小
   聚集、续传行为等特征做规则初筛，再用 GBDT / 序列模型精筛；
5. **标签口径**：按"请求发出时刻的意图"定义标签，并单独统计预取命中率。
