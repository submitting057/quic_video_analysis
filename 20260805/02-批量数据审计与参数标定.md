# 批量数据审计与参数标定

## 1. 目标

批量审计的目的不是为某个模型提前生成张量，而是回答以下问题：

- 原始数据是否足以构建可靠 Datagram 序列；
- 不同采集条件之间有哪些系统性差异；
- 哪些会话可以进入主训练集，哪些只能进入鲁棒性或故障集合；
- 固定长度、路径数、归一化、Burst 和播放定位参数应如何仅从训练集确定；
- 验证和测试中有多少样本超出训练域，是否需要重新设计表示而不是偷看测试集调参。

批量审计必须在数据划分前生成原始事实统计；任何会影响模型输入的拟合参数必须在划分后只使用训练集计算。

## 2. 两阶段审计

### 2.1 划分前事实审计

该阶段可以读取全部 capture，但只输出不依赖标签优化的事实：

- 文件哈希、格式和可读性；
- 捕获质量与解析覆盖率；
- 设备地址是否明确；
- Datagram 数量、长度、时间和路径事实；
- 原始文件与事件近重复关系；
- metadata、日志与 PCAP 是否一致；
- 是否存在多视频、广告或标签冲突。

该阶段不得决定归一化均值、固定长度、包长分档、Top-K 或分类阈值。

### 2.2 划分后训练域标定

完成 session 级分组划分后，仅使用训练集：

- 拟合长度与 IAT 变换参数；
- 确定固定长度适配器的 `L`；
- 确定时间 Bin 的 Top-K；
- 拟合数据驱动包长分档；
- 拟合 Burst 间隔；
- 标定自动播放定位参数；
- 生成训练词表或离散 embedding 索引。

验证集仅用于模型/阈值选择，测试集只用于最终评估。预处理不得根据验证或测试的溢出分布反向重拟合。

## 3. Capture 级画像

每个 capture 输出一行 `capture_quality.parquet`，至少包含：

```text

timestamp_precision_ns
snaplen_min
snaplen_max
capture_start_ns
capture_end_ns
duration_ns
record_count
captured_bytes
original_bytes
chronological_order
truncated_record_count

reassembly_failure_count
checksum_partial_count
giant_record_count
duplicate_candidate_count

parser_version
quality_status

```

关键分布按 `capture_id` 输出单独的长表，不把大数组塞进一行 JSON。

## 4. Datagram 与路径画像

### 4.1 长度分布

按以下维度分别统计：

```text
capture/session
traffic_scope
direction
path_local_id
observation_duration
collection_batch/device/network/region/app_version
```

统计项：

- 数量、字节总量、均值和标准差；
- P1/P5/P10/P25/P50/P75/P90/P95/P99/P99.5/P99.9/最大值；
- 0～65535 的固定对数直方图；
- 小控制包比例、近 MTU 包比例、异常巨型包比例；
- 不同长度定义之间的确定性差值检查。

连续长度必须始终保留。任何离散分档只作为适配器配置，不替代原始长度。

### 4.2 IAT 分布

分别统计：

```text
global_iat
path_iat
same_direction_path_iat
opposite_direction_transition_iat
```

零 IAT 单独计数；正 IAT 使用线性和 `log1p` 分布；负 IAT 计入质量错误。需要保存纳秒原值，绘图时再转换为微秒或毫秒。

### 4.3 事件密度

对候选观察时长 `5/10/30/60/120` 秒，按可用播放锚点生成临时统计窗，输出：

```text
event_count
bytes_c2s / bytes_s2c
packets_per_second
active_time_ratio
nonempty_time_bin_ratio
```

该临时窗只用于画像，不是最终训练样本。窗口边界和锚点来源必须记录。

### 4.4 路径覆盖

每个统计窗按“窗内”字节量和事件数分别排序，计算：

```text
top1/top2/.../top8 coverage
other coverage
path_count
new_path_arrival_times
```

不得使用完整 session 的排名替代窗口内排名。还应比较 `playback_quic_all` 与 `media_candidate` 的覆盖差异。

## 5. 协议和选择覆盖率

批量报告必须回答：

- 设备 UDP 中多少 Datagram 被 dissector 识别为 QUIC；
- 确认存在握手的 path 中，后续短头有多少不能被识别；
- UDP/443 覆盖多少确认 QUIC，遗漏多少非 443 QUIC；
- `quic || udp.port==443` 相对设备全部 UDP 的召回和假阳性情况；
- DNS 是否可见，A/AAAA/CNAME/TTL 映射覆盖多少 path 和字节；
- 有多少媒体候选 path 只能通过日志或流量模式识别；
- 是否存在 gQUIC、IETF QUIC 多版本、Version Negotiation、Retry、0-RTT 和迁移候选。

输出不能把 dissector 未识别等同于“不是 QUIC”。选择结果必须保留证据来源。

## 6. 播放定位画像

对同时具有日志与 PCAP 的训练候选会话，建立定位评估表：

```text
session_id
ground_truth_start_ns
ground_truth_end_ns
auto_start_ns
auto_end_ns
start_error_ms
end_error_ms
dns_visible
media_mapping_coverage
locator_features
```

重点统计：

- operate.log 与 debug_info 对齐误差；
- 自动定位的 MAE、P90、P95 和失败率；
- 不同设备、网络、地区、版本下的误差；
- DNS 不可见、缓存命中和多 CDN path 情况下的退化；
- 广告、预加载、后台上报和页面大对象造成的假起点。

自动定位只能使用部署时可获得的信息。训练日志用于标定目标和评价，不能直接成为部署模型输入。

## 7. 质量状态与处理策略

每个 capture 和 session 输出：

```text
quality_status = pass | conditional | quarantine | reject
```

### 7.1 `pass`

- 文件可完整读取；
- 客户端身份和方向明确；
- 截断、重组失败和异常巨型记录低于配置阈值；
- 播放阶段与标签一致；
- 没有未解决的多接口时间问题；
- 可以生成完整的模型基础事件表。

### 7.2 `conditional`

允许进入专门实验但不能静默并入主数据，例如：

- 无日志但自动定位置信度足够；
- 少量截断且不位于目标窗口；
- DNS 不可见但 QUIC 与播放证据明确；
- 存在少量广告候选或 codec/resolution 切换；
- capture point 与主数据不同。

### 7.3 `quarantine`

- 无法解释的 GRO/GSO；
- 时间戳或多接口时钟异常；
- 播放锚点不确定；
- 媒体候选与后台流量无法分离；
- 标签或原始文件存在待确认冲突。

### 7.4 `reject`

- PCAP 不可读；
- 关键区域大量截断或分片重组失败；
- 客户端身份未知；
- 明确播放了错误视频；
- 同一事件数据出现冲突标签；
- 处理结果不可重复。

各质量阈值必须在配置和数据报告中公开，不得只存在代码常量。

## 8. 固定长度 `L` 的拟合

完整基础事件表保持 ragged。只有需要固定长度的适配器才拟合 `L`。

### 8.1 按表示和观察范围分别拟合

不能为所有任务共享单一 `L`。至少按以下键拟合：

```text
traffic_scope
window_mode = duration | packet_prefix
observation_duration
adapter_name
```

默认规则：

```text
raw_L = 训练窗口事件数 P99.5
L = ceil(raw_L / length_multiple) * length_multiple
length_multiple 默认 256
```

不设置由单份样本推导的全局 16384。适配器可以另外声明设备内存允许的 `max_length`；若 `L` 超限，必须显式选择溢出策略，而不是静默截断。

### 8.2 溢出策略

- `prefix`：保留前 L 个事件，适用于明确的早期识别任务。
- `time_stratified`：将窗口划为固定子区间，在每个子区间按时间顺序确定性采样，保留全窗覆盖。
- `ragged_bucket`：不截断，按长度分桶动态 Padding，适用于支持变长批次的模型。
- `reject_overflow`：用于严格对照实验，超限窗口不进入该适配器。

每个模型视图必须保存：

```text
original_event_count
retained_event_count
overflow
overflow_strategy
covered_duration_ratio
```

验证和测试的溢出率只用于报告，不用于重新拟合 `L`。

## 9. Top-K 路径数拟合

在训练窗口内计算累计字节覆盖率。默认选择：

```text
K = 达到 99.5% 窗口内流量覆盖率所需的最小路径数
K_max = 8
```

如果 `K_max` 仍未达到目标，其余 path 合并到 `other`，并报告 `other_byte_ratio` 和 `other_event_ratio`。K 必须分别为不同 traffic scope 和观察时长拟合。

路径位置不能被赋予固定服务语义。分路径模型应使用共享编码器和排列不变融合；需要固定张量时，排名只对当前窗口有效。

## 10. 包长表示与分档

所有方案都保留连续长度。分档有三种显式策略：

### A. 语义固定边界

用于跨数据集可解释对照，例如：

```text
control_like: <= 200 B
intermediate: 201～1199 B
near_mtu: >= 1200 B
```

边界不追求类别平衡；中档稀疏是数据事实而不是错误。

### B. 训练集分位数

按方向或全体训练事件的指定分位数生成边界。该方案能减少空档，但必须保存边界并评估跨网络漂移。

### C. 对数等距直方图

对 `log1p(udp_payload_length)` 使用固定数量等宽 Bin。适合时间 Bin 模型保留比三档更细的尺度信息。

默认主输入使用连续长度、双向包数和字节数；A/B/C 作为可选直方图通道。禁止通过把 medium 上界从 1000B 改到 800B来“填充”本来稀疏的中档。

## 11. 归一化拟合

基础层不归一化。适配层从训练集拟合：

### 长度

支持：

- `linear_scale`：除以训练集高分位或显式协议尺度；
- `signed_log`：符号与 `log1p(abs(length))` 组合；
- `zscore_log`：对 `log1p(length)` 做训练集 Z-score；
- `embedding`：离散桶索引，词表只由训练集定义。

### IAT

默认：

```text
x = log1p(clip(iat_ns, 0, train_clip_ns))
y = (x - train_mean) / train_std
```

`train_clip_ns` 默认取训练集 P99.9，可配置硬上限防止极端空闲污染。首事件 IAT 通过单独 mask 处理，不参与均值和方差拟合。

### 相对时间

固定时长窗口使用 `timestamp_rel / window_duration`。固定包前缀使用实际秒数的训练集缩放或连续时间编码，不能按每条样本独立归一到 `[0,1]` 后丢失真实速度。

所有统计量写入 `preprocess_stats.json`，验证和测试遇到超范围值时按已冻结策略 clip 或映射到 OOV。

## 12. Burst 阈值标定

Burst 边界按同一 path、同一方向的连续 Datagram 计算，避免把请求和下行响应简单合并。

### 自适应默认方案

1. 收集训练集正 `path_iat`。
2. 对秒单位 IAT 取 `log10`。
3. 拟合两个一维 Gaussian component，分别表示段内间隔和段间空闲。
4. 取两分量后验概率相等的交点。
5. 将结果限制在 `[0.1, 2.0]` 秒。
6. 数据不足、模型不收敛或两分量不可分时回退 `1.0` 秒。

保留 `0.5/1.0/2.0` 秒三种固定阈值作为消融。阈值按 traffic scope 和网络大类拟合时，部署必须知道网络大类；否则使用全训练域统一阈值。

## 13. 自动播放定位标定

### 13.1 有监督训练会话

以日志锚点为 ground truth，候选特征只使用部署可见量：

- 媒体候选下行字节/包数；
- 全部确认 QUIC 的双向吞吐；
- 新 path 建立与大包连续性；
- DNS 映射是否有效；
- 相对 capture 起点时间。

选择参数时最小化起点绝对误差，同时限制页面对象、缩略图和后台上报导致的假起点率。

### 13.2 无监督降级

按固定短 Bin 统计媒体候选或确认 QUIC 的下行字节，以播放前候选区间为基线：

```text
threshold = median + mad_multiplier × MAD
```

默认 `mad_multiplier=6`，并要求多个连续 Bin 超阈值或一个明确的下行 Burst。实际默认值在训练域标定后冻结；如果无基线区间，则降低置信度而不是制造伪 ground truth。

### 13.3 输出

保存：

```text
locator_version
feature_config
fitted_thresholds
training_session_ids_hash
error_summary
fallback_order
```

## 14. 数据划分与重复控制

划分前建立以下 group：

- 相同 PCAP SHA-256；
- 相同 canonical 事件哈希；
- 明确来自同一次重放或同一采集任务；
- 同一 session 的分卷文件；
- 人工确认的近重复。

已知类评估至少提供：

- 随机 session 分组基线；
- 跨日期/批次；
- 跨设备或应用版本；
- 跨网络或地区；
- 多条件联合 holdout。

开放集还要求 unknown Video ID 在校准和测试间隔离。任何窗口化、起点抖动、丢包模拟、路径排列和多视图物化均在 split 之后完成。

## 15. `preprocess_stats.json` 契约

建议结构：

```json
{
  "schema_version": "1.0",
  "dataset_manifest_hash": "...",
  "training_split_hash": "...",
  "config_hash": "...",
  "created_by": {
    "pipeline_version": "...",
    "parser_version": "..."
  },
  "event_adapters": {},
  "time_bin_adapters": {},
  "burst_adapters": {},
  "path_k": {},
  "normalization": {},
  "playback_locator": {},
  "warnings": []
}
```

所有浮点统计保存足够精度；键按 adapter、traffic scope 和观察范围分层。加载时必须校验 schema、数据集和配置哈希，禁止跨不兼容数据集静默复用。

## 16. 批量报告

生成：

```text
quality/capture_quality.parquet
quality/session_quality.parquet
quality/exclusion_reasons.parquet
profiles/length_distribution.parquet
profiles/iat_distribution.parquet
profiles/window_density.parquet
profiles/path_coverage.parquet
profiles/protocol_coverage.parquet
profiles/playback_locator_errors.parquet
profiles/dataset_summary.json
provenance/preprocess_stats.json
```

`dataset_summary.json` 面向人工审阅，至少列出 pass/conditional/quarantine/reject 数量、各 split 的视频与会话数、主要质量风险、溢出率和域外比例。

## 17. 与单份实测数据的关系

[20260804](../20260804/README.md) 中 ENt4uip1MJ8 的统计可在获得原始文件后设置为 golden regression：

- 总包数约 77,212；
- 时长约 335.6 秒；
- 无分片、截断和明显 GRO/GSO；
- 媒体活动约从 11.06 秒持续到 326.57 秒；
- 某些 30 秒窗口事件数超过 8192。

允许因解析器版本、过滤口径和边界定义产生有解释的差异。任何差异必须记录原因，而不是为匹配文档数值修改通用算法。
