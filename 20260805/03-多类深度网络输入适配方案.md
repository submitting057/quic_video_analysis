# 多类深度网络输入适配方案

## 1. 设计原则

模型适配层只消费模型安全基础事件、窗口表和训练集拟合参数。它不能重新读取标签决定流量范围，也不能修改基础事实。

所有适配器遵守：

1. 使用 `session_id` 和 `window_id` 对齐不同视图。
2. 显式记录输入字段、方向符号、长度定义、归一化、截断和 Padding 规则。
3. 任何固定长度均配套 mask 和原始长度。
4. 多路径顺序不得被解释为稳定服务身份。
5. 训练时的随机增强不改变验证和测试产物。
6. 模型只看到观察窗内部的信息。

## 2. 统一适配器输入

每个窗口提供按时间排序的 ragged 事件：

```text
window_id
session_id
event_index
timestamp_rel_ns
global_iat_ns
path_iat_ns
direction = c2s | s2c
udp_payload_length
path_local_id
```

窗口元数据提供：

```text
traffic_scope
window_mode
window_start_offset_ns
window_duration_ns
original_event_count
split
```

适配器先应用 traffic scope 和窗口边界，再按保留事件重新计算：

```text
time_in_window_ns
view_global_iat_ns
view_path_iat_ns
path_window_token
```

`path_window_token` 可以按窗内首次出现或窗内 Top-K 规则生成。基础表的 session 级 `path_local_id` 用于一致性和回溯，不能替代窗口内重算。任何特征都不得引用窗外前一个事件。

标签通过 `window_id → session_id → labels.parquet` 在训练加载阶段连接，不写入张量文件。

## 3. 适配器公共输出

每种视图必须生成：

```text
index.parquet
arrays 或 shard 文件
adapter_manifest.json
```

`adapter_manifest.json` 至少包含：

```text
adapter_name
adapter_version
source_schema_version
traffic_scope
feature_names
tensor_layout
dtype
length_definition
sign_convention
normalization_stats_hash
overflow_strategy
padding_value
mask_semantics
config_hash
```

## 4. 方案 A：连续 Datagram 事件序列

### 4.1 最小输入 A1

```text
length_with_direction
global_iat
```

适合轻量 1D CNN、TCN、RNN 和早期原型。方向可以采用：

- `c2s_positive`：C2S 为正、S2C 为负；
- `s2c_positive`：S2C 为正、C2S 为负；
- `separate_channel`：长度始终非负，方向为独立数值或 embedding。

推荐新实验使用 `separate_channel`，避免正负号约定混淆；复现已有工作时显式选择相应符号。

### 4.2 完整输入 A2

连续特征：

```text
normalized_length
direction_value
normalized_global_iat
normalized_path_iat
relative_time
```

离散特征：

```text
path_token
optional_header_class
```

`optional_header_class` 只能作为明确的消融项，例如 `long/short/unknown`，默认关闭。真实 CID、端口和 QUIC Version 原值不进入主输入。

### 4.3 CNN/TCN 布局

```text
x_continuous: [B, F, L]
event_mask:   [B, L]
path_token:   [B, L]
path_mask:    [B, P]
```

模型中所有卷积、下采样和池化必须传播 mask。Padding 值默认为 0，但 0 可能是合法归一化结果，因此只依赖 mask 判定有效事件。

适用：

- 局部大包连续模式；
- 上下行交互；
- 轻量实时推断；
- 5～30 秒中等长度序列。

### 4.4 RNN 布局

```text
x_continuous: [B, L, F]
lengths:      [B]
event_mask:   [B, L]
```

优先使用 packed/ragged sequence 或 mask-aware recurrent block。最终状态不能直接取固定 `L-1`，应按真实长度索引或使用 masked pooling。

### 4.5 Transformer 布局

```text
x_continuous:       [B, L, F]
path_token:         [B, L]
attention_mask:     [B, L]
time_or_position:   [B, L]
```

位置表示提供三种策略：

- `event_index`：学习绝对/相对事件位置；
- `continuous_time`：使用相对时间和 IAT 编码；
- `hybrid`：事件索引与连续时间共同使用。

普通全局自注意力复杂度为 `O(L²)`。当 30 秒窗口达到上万事件时，不应直接使用完整全局注意力。必须选择：

- 局部/滑动窗口注意力；
- 分块 patch；
- CNN/TCN 下采样后接 Transformer；
- 改用时间 Bin 或 Burst 层级。

### 4.6 长序列策略

#### A. 早期前缀

```text
前 N 个 Datagram → 固定 L=N
```

适合回答“观察前 128/512/2048 个事件能否识别”。必须同时报告实际覆盖秒数分布，因为固定包数在不同吞吐下对应不同时间。

#### B. 确定性分时段采样

将固定时间窗切成 S 个子区间，每个区间保留至多 `L/S` 个事件，并保持时间顺序。子区间超限时按等距索引采样；不足时把剩余额度按确定规则分配给后续活跃区间。

该策略保留全窗覆盖，但改变局部包密度，必须与未采样时间 Bin 基线比较。

#### C. Ragged/分桶

按事件数分桶，在 batch 内 Padding 到当前最大长度。该策略信息损失最小，是离线 CNN/TCN/RNN 的推荐方案，但训练吞吐随长度波动。

## 5. 方案 B：多尺度时间 Bin

### 5.1 基本思想

时间 Bin 以固定墙钟时间为轴，将轻微重排和事件密度差异转为稳定聚合表示。[QCSD](https://www.usenix.org/system/files/sec22-smith.pdf) 同时讨论了按时间、长度和方向表示 packet trace；视频 Burst 工作也常使用固定时间聚合。

### 5.2 最细尺度

配置 `base_bin_ms`，建议候选集合为 `10/20/50/100 ms`，实际默认由训练实验决定。对每条窗口内 path、每个 Bin 统计：

```text
c2s_bytes
s2c_bytes
c2s_packets
s2c_packets
c2s_active
s2c_active
optional_length_histogram_c2s
optional_length_histogram_s2c
```

不得只保留下行，否则会丢失请求节奏和 ACK/控制交互。

### 5.3 张量布局

```text
x_bins:    [B, P, T, F]
path_mask: [B, P]
bin_mask:  [B, T]
```

`P = K + 1`，最后一条为 `other`。Top-K 只能按当前窗口内统计生成。

### 5.4 多尺度

粗尺度由最细尺度确定性求和或逻辑 OR 得到：

```text
20ms → 100ms → 500ms
```

字节和包数求和，active 标志取 OR。禁止对包数和字节数求平均，因为会改变总流量语义。

### 5.5 网络结构

- 每路径共享 1D/2D CNN 或 TCN，再进行集合融合；
- 路径维和时间维分离注意力；
- 多尺度独立编码后 concat/gated fusion；
- 将连续时间 Bin patch 成 Transformer token。

时间 Bin 适合 30～120 秒长窗口和全局 Transformer，是事件数非常高时的默认长程视图。

## 6. 方案 C：分路径集合输入

### 6.1 输入结构

每条 path 独立保存事件序列：

```text
x_paths:    [B, P, Lp, F] 或 ragged list[B][P][Lp,F]
event_mask: [B, P, Lp]
path_mask:  [B, P]
```

路径使用共享编码器：

```text
每路径事件 → Shared CNN/TCN/Transformer → path embedding
path embeddings → Set Pooling / DeepSets / Set Attention → session embedding
```

### 6.2 排列不变性

推荐模型本身使用排列不变操作。若网络仍依赖位置，训练时必须随机排列 path，并在测试中验证多次排列输出的一致性。

`path_local_id=0` 只能表示最先出现的 path，不能被解释为主视频 path。按窗内流量排名的张量位置也只表示本窗排名。

### 6.3 适用场景

- 多 CDN 并行；
- 控制、音频和视频候选 path 共存；
- NAT rebinding 或迁移导致五元组变化；
- 希望比较全局交错序列与路径内局部序列。

## 7. 方案 D：Burst 分层输入

### 7.1 Burst 定义

基础 Burst 默认在同一 path、同一方向上构造：

```text
相邻正 path_iat <= burst_gap → 同一 Burst
否则 → 新 Burst
```

阈值来自训练集拟合，固定 0.5/1/2 秒作为对照。Burst 只是一种确定性分层，不声称等于 HTTP 响应或 DASH Segment。

### 7.2 Burst 摘要

```text
direction
path_token
log_total_bytes
log_packet_count
duration
preceding_gap
mean_packet_length
length_std
near_mtu_ratio
control_like_ratio
within_burst_iat_stats
```

输出：

```text
x_burst:    [B, M, Fb]
burst_mask: [B, M]
```

### 7.3 包内事件

保留 Burst 内 packet-level 输入：

```text
x_packet:    [B, M, N, Fp]
packet_mask: [B, M, N]
burst_mask:  [B, M]
```

推荐组合：

```text
Packet CNN/TCN → burst embedding
Burst Transformer/RNN → session embedding
```

这比只输入人工摘要更接近 Packet-Level 学习，同时避免对整段上万事件做全局注意力。

### 7.4 截断

Burst 数 M 和包内长度 N 分别从训练集分布拟合。超限时必须记录：

- 被截断 Burst 数；
- 被截断包数；
- 被保留字节比例；
- 被保留时间比例。

## 8. 方案 E：多视图融合

### 8.1 对齐

事件、时间 Bin、路径集合和 Burst 均使用相同 `window_id`，但独立物化：

```text
event_view
time_bin_view
path_set_view
burst_view
```

融合模型只通过 manifest 中的 `window_id` 连接视图，不通过数组行号隐式对齐。

### 8.2 建议实验顺序

```text
单视图 A
→ 单视图 B
→ 单视图 C/D
→ A+B
→ A+D
→ A+B+D
```

每种单视图先形成完整基线，避免融合模型提升后无法解释来源。

### 8.3 融合方式

- embedding concat + MLP；
- gated fusion；
- cross-attention；
- mixture-of-experts；
- 训练时随机 view dropout，提高缺失视图鲁棒性。

## 9. 方案 F：受控字节视图

### 9.1 默认状态

字节视图默认 `enabled=false`。QUIC 密文预期接近伪随机，且稳定头字段、地址或捕获层级可能形成 shortcut。它只用于明确的字节模型研究，例如 [ET-BERT](https://arxiv.org/abs/2202.06335) 或 packet-instance Transformer，不进入元数据主线。

### 9.2 三种模式

#### F1 完整捕获帧

保留原始 frame bytes，信息最完整但 shortcut 和隐私风险最高。只允许在受控环境中使用。

#### F2 UDP Payload

剥离 Link/IP/UDP Header，只保留 UDP Payload。仍包含 QUIC 可见头和密文。

#### F3 去稳定头字节

按解析结果剥离 Link/IP/UDP Header，并对明确的 CID、版本或其他稳定头范围执行置零/专用 mask。不能在无法可靠定位字段时猜测删除偏移。

### 9.3 张量

```text
packet_bytes: [B, Pkt, Byte]
packet_mask:  [B, Pkt]
byte_mask:    [B, Pkt, Byte]
```

或者将一个 Burst 内若干 Datagram 按明确分隔 token 拼接。每个 Datagram 边界必须可恢复，不能无分隔地把不同包拼成一条字节流。

### 9.4 强制检查

- 用只含头字段的模型测试 shortcut；
- 随机替换密文但保留长度，比较性能；
- CID/IP/端口/绝对时间消融；
- 跨设备、版本、日期和地区 holdout；
- 记录原始字节访问权限和输出加密/清理策略。

如果模型只在随机 session 划分有效、跨采集域崩溃，不得将结果解释为视频内容识别能力。

## 10. 包长分档通道

时间 Bin 和 Burst 可选择：

- `semantic_fixed`：控制/中间/近 MTU；
- `train_quantile`：训练集分位数；
- `log_histogram`：对数等距；
- `none`：只保留连续字节数和包数。

无论哪种方案，基础连续长度和总字节数不能删除。分档边界写入适配器 manifest，并使用训练集冻结值。

## 11. 时间和位置编码

不同模型可选择：

- 原始相对时间经训练集尺度归一化；
- `log1p(global_iat)` / `log1p(path_iat)`；
- 正弦连续时间编码；
- 可学习事件位置 embedding；
- 相对位置偏置；
- Time2Vec 或其他连续时间映射。

禁止按每个 session 单独把时间压缩到相同形状后又不保留真实持续时间，因为下载速度和 Burst 间隔可能是信号，也可能是网络 shortcut，必须通过显式消融评估。

## 12. Mask 语义

统一定义：

```text
True / 1  = 有效
False / 0 = Padding 或不存在
```

至少区分：

```text
event_mask
path_mask
bin_mask
burst_mask
packet_mask
byte_mask
first_iat_mask
```

不要用包长为 0 推断 Padding；合法 UDP Payload 可以为 0，归一化后的特征也可能为 0。

卷积下采样后 mask 使用与感受野一致的 max/any pooling；平均池化和 attention softmax 必须排除 Padding。

## 13. 训练增强边界

允许且必须在 split 后执行：

- 播放起点偏移；
- 事件随机丢弃，模拟捕获丢包；
- 小范围时间抖动，但不得产生乱序或负 IAT；
- 路径排列；
- view dropout；
- 在协议约束下的 MTU/聚合扰动实验。

禁止：

- 根据测试域统计生成增强；
- 任意交换包序破坏 QUIC/网络语义后声称网络鲁棒性；
- 把同一增强前后的样本放入不同 split；
- 使用 `video_id` 选择增强强度。

[Rosetta](https://www.usenix.org/conference/usenixsecurity23/presentation/xie) 表明网络环境变化会显著改变包长序列。QUIC 与 TCP 机制不同，因此增强必须针对 QUIC 和捕获环境重新验证，不能直接照搬 TCP 重传语义。

## 14. 推荐适配器集合

首轮实现建议同时提供以下 adapter，而不预先指定哪一个必然最好：

```text
event_minimal_cnn
event_full_tcn
event_full_transformer_local
time_bin_multiscale
path_set_event
burst_hierarchical
multiview_event_bin
bytes_optional
```

所有 adapter 从同一基础表重建，使用相同 split 和 `window_id`，使性能差异主要反映表示和模型选择。

## 15. 张量验收

每个 adapter 必须通过：

- Shape 与 manifest 一致；
- mask 与原始长度一致；
- Padding 后有效区域数值不变；
- 改变 Padding 长度不改变 mask-aware 模型输出；
- path permutation 对集合模型输出影响在容差内；
- 不同视图的 `window_id` 一一对应；
- 溢出窗口可追溯到原始事件；
- 验证/测试仅使用冻结的训练统计；
- 张量和 manifest 内容哈希可重复。
