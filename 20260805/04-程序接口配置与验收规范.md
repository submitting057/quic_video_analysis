# 程序接口、配置与验收规范

## 1. 实现目标

预处理程序应作为可重复执行的数据流水线，而不是一段从 PCAP 直接输出单个 NumPy 文件的脚本。每个阶段具有确定输入、确定输出、schema 版本、配置哈希和质量报告。

推荐命令链：

```text
index_captures
→ audit_captures
→ extract_datagrams
→ locate_playback
→ select_quic_paths
→ build_model_base
→ assign_group_splits
→ fit_preprocess_stats
→ materialize_model_view
→ validate_artifacts
```

阶段失败时保留已完成的只读产物和错误报告，不产生看似完整的半成品输出。

```text
│   ├── event_lineage.parquet
│   └── path_evidence.parquet
├── events/

├── quality/

```

Parquet 用于结构化表；大张量可以使用 Zarr、HDF5、NPZ shard、Arrow Tensor 或框架原生格式，但格式必须在 adapter manifest 中声明。不要把全部样本写成单个不可增量恢复的超大文件。

## 3. Schema 公共约定

### 3.1 类型

- 时间统一为有符号 `int64` 纳秒。
- 长度和计数使用足够位宽的无符号整数；进入 Parquet 前确认目标库的兼容性。
- 枚举在 schema registry 中定义允许值，未知值使用明确 `unknown`，不使用空字符串替代。
- 多值证据使用 list 类型或关联长表，不用逗号拼接字符串。
- 可空字段必须说明 null 语义。

### 3.2 主键

```text
captures:           capture_id
sessions:           session_id
phases:             phase_id
windows:            window_id
datagrams_audit:    capture_id + frame_number + interface_id
events_model_base:  session_id + event_index
model view index:   window_id + adapter_sample_id
```

所有主键在单次构建内唯一且稳定。重新运行相同版本和配置必须得到相同 ID；随机 UUID 只能来自上游真实标识，不能在每次预处理时重新生成。

## 4. 核心表契约

### 4.1 `captures.parquet`

```text
capture_id: string
pcap_uri: string                 # 敏感区使用，不进入模型产物
pcap_sha256: fixed string
file_size_bytes: int64
file_format: enum
encapsulation: enum
interface_count: int32
timestamp_precision_ns: int64?
snaplen_min/max: int32?
capture_start/end_ns: int64
client_ipv4: list<string>
client_ipv6: list<string>
metadata_uri/log_uris: string/list<string>
collection_batch: string
device_key/app_version/network_profile/region: string
parser_version: string
quality_status: enum
```

`client_ipv4/ipv6` 属于审计区字段，后续模型基础表不得保留。

### 4.2 `sessions.parquet`

```text
session_id: string
capture_ids: list<string>
playback_start/end_ns: int64?
anchor_source: operate_log | debug_info | automatic | fallback | unknown
anchor_confidence: float32
estimated_error_ms: float32?
contains_foreign_video_id: bool
contains_ad_candidate: bool
target_id_consistency: float32?
quality_status: enum
quality_reasons: list<string>
```

### 4.3 `labels.parquet`

```text
session_id: string
video_id: string
is_target_known: bool
scpn: string?
codec: string?
resolution_width/height: int32?
frame_rate: float32?
device_key/app_version/network_profile/region/collection_date: string
quality_group: string
```

`labels.parquet` 与模型事件物理隔离。除 `session_id` 外，不复制到模型视图。

### 4.4 `datagrams_audit.parquet`

```text
capture_id
frame_number
interface_id
timestamp_ns
frame_length
captured_length
link_type
vlan_ids
ip_version
src_ip/dst_ip
src_port/dst_port
raw_path_key
ip_fragment_id
fragment_offset
more_fragments
fragment_count
reassembly_status
udp_length
udp_payload_length
direction
udp_payload_hash?
quic_dissected
quic_header_forms
quic_version_values
dcid_values/scid_values
dns_evidence_ids
duplicate_group_id?
is_truncated
is_giant_record
checksum_status
selection_reasons
quality_flags
```

如果出于隐私不保存 UDP Payload 哈希，应使用捕获内短期 keyed hash，并在 provenance 中说明；哈希只用于重复审计，不进入模型。

### 4.5 `events_model_base.parquet`

```text
session_id: string
event_index: int64
timestamp_rel_ns: int64
global_iat_ns: int64?
path_iat_ns: int64?
direction: c2s | s2c
udp_payload_length: int32
path_local_id: int32
in_playback_quic_all: bool
in_media_candidate: bool
quality_flags: list<enum>
```

不得出现原始地址、端口、CID、DNS 名、绝对时间、文件名和 `video_id`。

基础事件到审计记录的受控映射单独保存为敏感区 `event_lineage.parquet`，不进入 `events_model_base.parquet` 或模型视图。

### 4.6 `windows.parquet`

```text
window_id
session_id
traffic_scope
window_mode
start_offset_ns
duration_ns?
packet_prefix_length?
anchor_source
augmentation_id
original_event_count
first/last_event_index
split
```

`duration_ns` 与 `packet_prefix_length` 根据 `window_mode` 二选一，不能同时为空或同时生效。

## 5. 模块接口

语言实现可以不同，但行为应等价于以下接口。

### 5.1 `index_captures`

```python
index_captures(input_roots, manifest_sources, config) -> CaptureIndexResult
```

职责：

- 发现 PCAP/PCAPNG 及支持的压缩格式；
- 计算哈希并关联 metadata/log；
- 解析采集命名仅作为辅助，metadata 优先；
- 检测物理重复和缺失配套文件；
- 生成 `captures.parquet` 初始版本。

同一 SHA-256 关联冲突 metadata 时必须报错并隔离。

### 5.2 `audit_captures`

```python
audit_captures(captures, config) -> CaptureAuditResult
```

职责：调用 capinfos/解析库，检查格式、时间、snaplen、接口、截断、分片、offload、巨型记录和捕获丢包。输出 capture 质量表和逐项审计统计。

### 5.3 `extract_datagrams`

```python
extract_datagrams(captures, config) -> DatagramExtractionResult
```

职责：

- 提取设备相关全部 UDP 与 DNS；
- 执行 IP 重组；
- 规范化方向和五元组；
- 收集 QUIC/DNS/CID 证据；
- 检测镜像重复候选；
- 生成 `datagrams_audit.parquet`。

解析器必须固定字段 occurrence 策略。QUIC 多值字段不能用“只取第一个值”静默丢失 coalescing 证据。

### 5.4 `locate_playback`

```python
locate_playback(captures, datagrams, logs, locator_config) -> PlaybackLocationResult
```

职责：按优先级使用 operate.log、debug_info、自动检测和 fallback，输出 sessions/phases 与定位证据。无可用定位时返回低置信 `unknown`，不能默认把 PCAP 全部时长当成高质量播放窗口。

### 5.5 `select_quic_paths`

```python
select_quic_paths(datagrams, sessions, selection_config) -> PathSelectionResult
```

职责：为 path 计算 QUIC 候选得分、DNS 媒体候选标记和选择原因，生成 `playback_quic_all` 与 `media_candidate` 范围。

选择规则更改必须改变配置哈希和模型基础表版本。

### 5.6 `build_model_base`

```python
build_model_base(datagrams, sessions, selected_paths, config) -> ModelBaseResult
```

职责：

- 稳定排序；
- 分配首次出现顺序的 `path_local_id`；
- 计算相对时间和 IAT；
- 移除模型禁止字段；
- 输出 `events_model_base.parquet`；
- 计算 canonical event hash。

出现负 IAT、未知方向或审计事件计数无法对账时，该 session 失败而不是裁剪修复。

### 5.7 `assign_group_splits`

```python
assign_group_splits(sessions, labels, duplicate_groups, split_config) -> SplitResult
```

职责：按 session/批次/日期/设备/网络/地区等分组生成 split，隔离 unknown Video ID，并验证所有派生样本继承同一 split。

### 5.8 `fit_preprocess_stats`

```python
fit_preprocess_stats(train_events, train_windows, adapter_specs, config) -> PreprocessStats
```

输入 API 只能接受训练 split；传入 validation/test 时必须拒绝。输出固定长度、Top-K、归一化、分档、Burst 和定位参数及来源哈希。

### 5.9 `materialize_model_view`

```python
materialize_model_view(events, windows, stats, adapter_spec) -> ModelViewResult
```

职责：生成具体张量、mask、index 和 manifest。加载 stats 时校验数据集、split、schema 和配置哈希。

### 5.10 `validate_artifacts`

```python
validate_artifacts(dataset_root, validation_config) -> ValidationReport
```

职责：执行 schema、引用、计数、哈希、泄漏、划分、mask、多视图对齐和 golden regression 检查。任何 error 使命令非零退出；warning 进入报告但不阻止条件数据集生成。

## 6. 配置结构

配置采用 YAML，完整生效配置复制到 provenance。建议顶层：

```yaml
schema_version: "1.0"

io: {}
parser: {}
quality: {}
traffic_selection: {}
playback_locator: {}
windowing: {}
representations: {}
normalization: {}
splitting: {}
privacy: {}
output: {}
```

### 6.1 `io`

```yaml
io:
  input_roots: []
  manifest_sources: []
  allowed_capture_formats: [pcap, pcapng]
  allow_compressed: true
```

### 6.2 `parser`

```yaml
parser:
  engine: tshark
  two_pass: true
  name_resolution: false
  ip_reassembly: true
  include_ipv6: true
  first_pass_scope: all_client_udp
  quic_multi_value_policy: preserve_all
```

`name_resolution=false` 避免外部解析改变结果；DNS 映射从 PCAP 内证据构建。

### 6.3 `quality`

```yaml
quality:
  truncated_policy: exclude_datagram
  reassembly_failure_policy: exclude_datagram
  giant_record_policy: quarantine
  duplicate_policy: remove_proven_only
  negative_iat_policy: fail_session
  unknown_direction_policy: exclude_datagram
  require_readable_capture: true
```

允许的巨型策略仅为 `quarantine | segment_with_metadata | retain_for_robustness`。未知枚举必须报错。

### 6.4 `traffic_selection`

```yaml
traffic_selection:
  scopes: [playback_quic_all, media_candidate]
  default_scope: playback_quic_all
  first_pass_filter: all_client_udp
  dns_patterns: ["*.googlevideo.com"]
  dns_ttl_aware: true
  quic_threshold_mode: train_calibrated
  quic_score_threshold: null
  include_borderline_in_audit: true
```

`quic_threshold_mode` 允许 `train_calibrated | explicit`。选择 `explicit` 时 `quic_score_threshold` 必须给值；选择 `train_calibrated` 时只使用具有人工/握手证据的训练 capture 标定并写入 stats。

### 6.5 `playback_locator`

```yaml
playback_locator:
  priority: [operate_log, debug_info, automatic, fallback]
  automatic_method: robust_burst
  baseline_method: median_mad
  mad_multiplier: 6.0
  supervised_calibration: true
  fallback_offset_seconds: null
  min_confidence_for_main_dataset: 0.8
```

`mad_multiplier` 是初始默认，训练域标定后写入 stats；不能在测试集上改动。

### 6.6 `windowing`

```yaml
windowing:
  duration_seconds: [5, 10, 30, 60]
  packet_prefix_lengths: [128, 512, 2048]
  start_offsets_seconds: [0]
  train_augmentation_offsets_seconds: [-5, 0, 5, 10]
  clip_to_playback_bounds: true
```

增强偏移只作用于 train。负偏移越过可用捕获范围时丢弃该增强，不用 Padding 伪造播放前数据。

### 6.7 `representations`

```yaml
representations:
  event:
    enabled: true
    layout: transformer
    features: [length, direction, global_iat, path_iat, relative_time]
    sign_convention: separate_channel
    target_length: train_p99_5
    length_multiple: 256
    overflow_strategy: ragged_bucket
  time_bin:
    enabled: true
    base_bin_ms: 20
    derived_bin_ms: [100, 500]
    path_k: train_coverage_99_5
    path_k_max: 8
    length_bins: semantic_fixed
  burst:
    enabled: true
    gap_method: adaptive_gmm
    fallback_gap_seconds: 1.0
  bytes:
    enabled: false
    mode: udp_payload
```

### 6.8 `normalization`

```yaml
normalization:
  fit_split: train
  length_method: zscore_log
  iat_method: zscore_log
  iat_clip_quantile: 0.999
  relative_time_method: window_fraction
  unknown_bucket_policy: oov
```

`fit_split` 只允许 `train`。

### 6.9 `splitting`

```yaml
splitting:
  strategy: grouped
  group_fields: [duplicate_group, session_id, collection_batch]
  holdout_axes: [collection_date, device_key, network_profile, region]
  unknown_video_id_disjoint: true
  seed: 0
```

具体训练/验证/测试比例属于实验配置，但每次生成必须保存 session 清单和哈希。

### 6.10 `privacy`

```yaml
privacy:
  model_forbidden_fields:
    [video_id, ip, port, mac, cid, dns_name, filename, absolute_time, region, device_key]
  byte_view_requires_explicit_enable: true
  store_payload_hash: keyed
  export_audit_tables: false
```

### 6.11 `output`

```yaml
output:
  table_format: parquet
  tensor_format: zarr
  shard_target_mb: 512
  compression: zstd
  atomic_publish: true
```

`atomic_publish=true` 表示先写临时构建目录，全部验收通过后再发布为正式版本。

## 7. 配置校验

程序启动前必须检查：

- 未知字段和未知枚举报错；
- 相互冲突的字段报错；
- `media_candidate` 启用但未配置 DNS/日志/选择证据时给出明确警告；
- `segment_with_metadata` 没有分段元数据时拒绝运行；
- bytes 视图启用时要求显式隐私确认和输出权限；
- train stats 与 adapter schema 不匹配时拒绝加载；
- 固定时长窗口和固定包前缀参数合法；
- 输出路径不覆盖不同配置的已发布数据集。

## 8. 错误与警告模型

结构化错误至少包含：

```text
error_code
severity = warning | session_error | capture_error | dataset_error
capture_id/session_id/frame_number
stage
message
evidence
recommended_action
```

示例 error code：

```text
CAPTURE_UNREADABLE
METADATA_MISMATCH
TRUNCATED_DATAGRAM
REASSEMBLY_FAILED
UNEXPLAINED_GIANT_RECORD
UNKNOWN_DIRECTION
NEGATIVE_IAT
LABEL_CONFLICT
SPLIT_LEAKAGE
STATS_HASH_MISMATCH
FORBIDDEN_MODEL_FIELD
VIEW_ALIGNMENT_ERROR
```

错误不能只写自由文本日志；排除原因必须进入结构化表。

## 9. 可复现性

每个发布版本记录：

- 原始 capture manifest 哈希；
- 每个 PCAP SHA-256；
- pipeline Git commit 或版本；
- TShark/Wireshark/解析库版本；
- schema 版本；
- 生效配置及其 SHA-256；
- split session 清单哈希；
- train stats 哈希；
- 每张输出表和每个 shard 的内容哈希。

相同输入、版本和配置重复运行时，除明确声明的非确定训练增强外，所有表行数、排序、ID 和内容哈希必须一致。随机过程统一使用显式 seed，并按 session/window 派生子 seed，避免并行顺序改变结果。

## 10. 单元测试

### 捕获与解析

- pcap 与 pcapng；
- 单接口和多接口；
- Ethernet、Linux cooked 等支持的 LinkType；
- IPv4/IPv6、VLAN；
- UDP 零 Payload；
- IP 分片成功/失败；
- snaplen 截断；
- 时间戳乱序与相同时间戳；
- checksum offload/partial checksum；
- 有/无元数据的 GRO/GSO；
- QUIC coalescing 多值字段；
- 零长度 CID 与不可见短头 CID；
- DNS CNAME、A、AAAA、TTL 过期和 IP 复用。

### 事件语义

- 正反向映射到同一 path；
- 客户端地址驱动方向判断；
- `udp_payload_length = udp_length - 8`；
- 一个重组 Datagram 只生成一个事件；
- `path_local_id` 按首次出现稳定分配；
- IAT 在筛选与排序后计算；
- 首事件 IAT 为 null；
- 模型表不含禁止字段。

### 播放定位

- operate.log 优先于其他来源；
- debug_info 时间偏移正确；
- 自动定位降级和置信度；
- 广告/其他 Video ID 标记；
- 无证据时不伪造高置信起点。

## 11. 泄漏测试

必须自动验证：

- 同一 session 的窗口和增强不跨 split；
- 相同 capture/event hash 不跨 split；
- unknown calibration/test Video ID 不重叠；
- `fit_preprocess_stats` 输入中没有 validation/test；
- Top-K 和 path 排名只读取窗口内部事件；
- 起点增强在 split 后生成；
- 模型视图不含 IP、端口、CID、DNS 名、文件名、绝对时间、地区和设备 key；
- 标签只能在 DataLoader/训练阶段按 `session_id` 连接；
- 测试集分布不参与固定长度、分档、Top-K 或归一化。

## 12. 适配器测试

每个 adapter 检查：

- 张量 layout、dtype 和 feature 顺序与 manifest 一致；
- mask 计数等于保留事件数；
- Padding 值不被当成有效事件；
- CNN/TCN mask 下采样正确；
- RNN 最终状态按真实长度获取；
- Transformer attention 不访问 Padding；
- path 集合模型对排列不敏感；
- 时间 Bin 粗尺度可由细尺度确定性复算；
- Burst 摘要与包内事件总量一致；
- 多视图 `window_id` 对齐；
- 溢出策略确定且报告覆盖率；
- byte 视图的帧边界和 header stripping 可回溯。

## 13. 集成与 Golden Regression

### 13.1 合成 fixture

仓库应提供小型合成 capture，覆盖所有边界情况，不依赖敏感真实流量。合成 fixture 的预期 Datagram、路径、时间和质量标志必须人工可审计。

### 13.2 真实 golden capture

获得授权的 ENt4uip1MJ8 原始文件后，建立私有或受控 golden test。预期参考 [20260804](../20260804/README.md)：

- 约 77,212 个捕获记录；
- 总时长约 335.6 秒；
- 无 IP 分片、截断和明显 GRO/GSO；
- 自动媒体活动区间接近 11.06～326.57 秒；
- 30 秒高吞吐窗口事件数可能超过 8192。

测试使用容差和解释性检查，不要求不同 Wireshark 版本的 QUIC 细字段计数完全相同。Datagram 数、长度和时间等基础事实应保持稳定。

## 14. 数据集验收门

正式发布必须满足：

- 所有 pass capture 可完整读取并有 SHA-256；
- session、标签、PCAP 和日志关联一致；
- 一行基础事件对应一个有效 UDP Datagram；
- 分片、截断、重复和 offload 决策可追溯；
- 所有 IAT 非负，首事件 null 语义一致；
- 模型表无禁止字段；
- split 和 unknown 隔离测试通过；
- train stats 来源和哈希明确；
- 每种适配器的溢出率、路径覆盖和 mask 检查有报告；
- 相同输入重复构建得到相同内容哈希；
- 所有 error 已解决或对应 capture/session 被明确排除；
- warning 数量和质量组分布写入数据集摘要。

## 15. 文档和代码验收

- 文档中的字段名与 schema registry 一致；
- 所有 A/B/C 策略在配置中有枚举、默认值和失败行为；
- CLI `--help` 或 API 文档列出输入输出和退出码；
- 新增 adapter 不需要重解析或覆盖基础事件表；
- schema 破坏性变更提升主版本并提供迁移说明；
- 所有外部事实引用 RFC、Wireshark 官方资料或原始论文；
- 不在日志、配置样例或错误报告中暴露秘密和私人路径。
