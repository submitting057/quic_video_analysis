# 五元组、流、路径与 QUIC 连接的关系

所谓“PCAP 五元组”不是 PCAP 文件头中的固定字段，而是解析器从 IP 和 TCP/UDP 头中提取的流量标识：

```text
(源 IP, 源端口, 目的 IP, 目的端口, 传输层协议)
```

例如：

```text
(192.168.1.20, 53124, 203.0.113.10, 443, UDP)
```

## 字段来源

| 字段 | 来源 |
| --- | --- |
| 源/目的 IP | IPv4 或 IPv6 头 |
| 源/目的端口 | TCP 或 UDP 头 |
| 传输层协议 | IPv4 Protocol 或 IPv6 Next Header |

严格按字段顺序时，下列两个五元组不同：

```text
客户端 → 服务器：
(192.168.1.20, 53124, 203.0.113.10, 443, UDP)

服务器 → 客户端：
(203.0.113.10, 443, 192.168.1.20, 53124, UDP)
```

进行双向会话分析时，工具通常会将正向和反向规范化为一个 Conversation。

## 五元组与 PCAP 文件格式的区别

```text
PCAP Global Header   → 描述文件版本、端序、时间精度和 LinkType
PCAP Record Header   → 描述单个捕获记录的时间和长度
Captured Packet Data → 保存 Ethernet/IP/UDP/QUIC 等原始字节
五元组               → 从 Captured Packet Data 中解析得到
```

因此五元组是分析概念，不是经典 PCAP Record Header 的组成部分。

## 与 TCP 的关系

TCP 连接通常可以由五元组识别，但为了区分同一五元组在不同时间发生的多次连接，还应结合：

```text
时间
SYN / FIN / RST
TCP 序列号
```

## 与 UDP 的关系

UDP 本身没有连接建立和关闭过程。所谓 UDP Flow 通常是分析工具采用的工程定义：

```text
相同五元组 + 空闲超时
```

例如超过 30 秒没有新数据后，后续数据可能被划分为一条新流。该超时属于分析策略，不属于 UDP 或 PCAP 格式。

## 与 QUIC 的关系

QUIC 运行在 UDP 上，因此也有五元组；但 QUIC 支持连接迁移，同一逻辑连接可能跨越多个五元组。

例如手机从 Wi-Fi 切换到移动网络：

```text
迁移前：
(192.168.1.20, 53124, 203.0.113.10, 443, UDP)

迁移后：
(100.64.20.8, 62001, 203.0.113.10, 443, UDP)
```

从五元组看是两条路径，从 QUIC 逻辑看可能仍是同一连接。

QUIC Connection ID 也不能被简单视为永久连接主键：

- 端点可以提供和轮换多个 CID。
- 路径迁移和 NAT 重绑定可能改变五元组。
- 被动观察者未必能看到加密的 CID 管理帧。
- 零长度 CID 或连接复用会进一步增加会话恢复难度。

比较稳妥的概念是：

```text
五元组        → 当前可观察的网络路径
匿名 path_id  → 数据集中对路径关系的无身份编号
QUIC CID      → QUIC 端点使用的路由/连接标识之一
播放会话      → 研究者额外定义和标注的应用级样本
```

## NAT、VPN 和抓包位置

NAT 会修改观察到的 IP 和端口：

```text
内网侧：192.168.1.20:53124 → 203.0.113.10:443
公网侧：198.51.100.5:40001 → 203.0.113.10:443
```

VPN 或隧道还可能同时存在外层和内层五元组。抓包位置及是否能够解密隧道，决定分析器能看到哪一层。
